# What is the difference between local and cloud LLMs?

> Week 06 – Working with LLMs and Model APIs · Question 6

## Short Answer
A local LLM runs on hardware you control (laptop, on-prem server) using open-weight models via tools like Ollama or Hugging Face `transformers`; a cloud LLM runs on a provider's servers and you access it through an API (e.g. Anthropic's Claude). Local gives privacy, offline use and no per-token fees but is limited by your hardware; cloud gives the most capable models, scale and zero ops but costs per token and sends data to a third party.

## Detailed Explanation

```
 LOCAL                                   CLOUD
 your app ─► localhost:11434 ─► GPU     your app ─► HTTPS ─► provider API ─► data-center GPUs
 (data never leaves machine)            (data sent to provider under their data policy)
```

| Dimension | Local LLM | Cloud LLM |
|---|---|---|
| Model quality | Good small/medium open models | Frontier models (e.g. claude-opus-5-5) |
| Cost model | Upfront hardware + electricity | Pay per input/output token |
| Privacy | Data stays on your machine | Governed by provider terms, regions, retention |
| Latency | No network hop; but slower hardware | Network hop; very fast hardware |
| Scale | Limited by your GPUs | Elastic, subject to rate limits |
| Ops burden | You manage updates, hardware, serving | Provider manages it |
| Offline | Yes | No |
| Customisation | Full (fine-tune weights, any quantization) | Via prompts, tools, provider fine-tuning options |

**When to choose which:**
- *Local*: sensitive data (health, legal), air-gapped environments, high-volume simple tasks, learning/experimentation.
- *Cloud*: complex reasoning, long context, multimodal, production apps needing reliability without an ML-ops team.
- *Hybrid*: route easy/private requests to a local model, hard ones to the cloud.

## Example
**Analogy:** Local is cooking at home (you own the kitchen, ingredients stay private, limited by your stove); cloud is ordering from a restaurant (better chef, pay per dish, food prepared elsewhere).

A tiny router that uses the same interface for both:

```python
import requests
import anthropic

def ask_local(prompt: str) -> str:
    r = requests.post("http://localhost:11434/api/chat", json={
        "model": "llama3.2", "stream": False,
        "messages": [{"role": "user", "content": prompt}]}, timeout=120)
    r.raise_for_status()
    return r.json()["message"]["content"]

def ask_cloud(prompt: str) -> str:
    client = anthropic.Anthropic()  # reads ANTHROPIC_API_KEY
    resp = client.messages.create(model="claude-sonnet-5-5", max_tokens=512,
                                  messages=[{"role": "user", "content": prompt}])
    return resp.content[0].text

def ask(prompt: str, contains_pii: bool) -> str:
    # Keep private data local; send everything else to the stronger cloud model
    return ask_local(prompt) if contains_pii else ask_cloud(prompt)

print(ask("Summarise: patient John, 54, reports chest pain.", contains_pii=True))
# Expected: a one-line summary generated by the local llama3.2 model
```

## Common Mistakes / Misconceptions
- **"Local is free."** Hardware, power and engineering time cost money; at low volume cloud is often cheaper.
- **"Cloud means my data trains their model."** Policies differ — commercial API terms often exclude training on your data by default, but read the provider's current data-use policy.
- **Comparing a 3B local model to a frontier cloud model on hard tasks** and concluding "local is useless" — match model size to task.
- **Ignoring rate limits** in cloud plans; design retries and backoff.

## Key Takeaways
- Local = control, privacy, offline; limited by your hardware.
- Cloud = best models, scale, no ops; per-token cost and data leaves your network.
- Many production systems are hybrid with a routing layer.
- Decide using quality needs, data sensitivity, volume and team skills.
